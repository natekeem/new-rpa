04 / 10 · Plugin First

과제는 독립적인 배포 자산이다

Agent는 실행 주체, Plugin은 배포·버전 관리 단위입니다. Common Plugin은 복사하지 않고 버전을 고정해 참조합니다.

폴더 구조 (예시)

attendance-report/        # Task Plugin (예시)
├─ manifest.json        # 이름·버전·권한·의존성
├─ agent/main.md        # Main Agent
├─ skills/workflow.md   # Workflow Skill
├─ skills/recovery.md   # (선택) Recovery Skill
├─ scripts/             # 결정적 실행 코드
├─ assets/              # 이미지·템플릿
├─ tests/               # 회귀 테스트
└─ hooks/entrypoint     # 시작·종료·승인 훅
deps: common-mail, common-attendance  (lock · 복사 안 함)

Agent와 Plugin의 차이

구분역할
Agent실행 주체 · 상황 판단 · 도구 호출
Plugin배포 · 버전 관리 · 권한 단위
Common Plugin복사 없이 버전 고정 참조
Claude Code Plugin참고 모델 (자체 중립 표준 사용)

Git · 배포 · 운영 버전 — 소스, 배포본, 운영 Release는 서로 다른 책임

1모든 요소가 필수는 아님

과제 유형에 따라 필요한 요소만 선택해 구성합니다.

2중립 패키지 표준

Claude Code Plugin은 참고 모델이며 자체 중립 표준을 사용합니다.

3불변 배포본

Store의 artifact는 수정하지 않고 새 버전으로 배포합니다.

4롤백과 재현성

롤백은 이전 승인 패키지를 지정하며 실행마다 Profile을 기록합니다.

TCO 비교 공식

현행 연간 TCO = A360 라이선스 + VDI + 유지보수 + 운영 인력 + 공통 인프라
신규 연간 TCO = 기존 병행 비용 + 신규 개발/운영 + VDI/추론 + 보안/CI/저장소
연간 순효과 = 기존 대비 반복비용 절감 + 검증된 업무시간 절감 가치 - 신규 반복비용
투자 회수 = 초기 투자비 / 연간 순효과 (순효과 > 0인 경우)

VDI 감축과 인력 절감은 자동으로 계산하지 않습니다. 로컬 LLM이 라이선스 비용을 줄일 수 있으나 VDI CPU/RAM 증설, 배포·운영 및 개발 비용이 발생합니다. 기존 비용·과제 실행 빈도·평균 시간·장애 공수는 제공되지 않았으므로 정량 ROI는 미확정입니다.
